# Release notes — GKOS-2026-08-05 v0.77 (UNPUBLISHED)

**Do not cite this as a released standard.** The published baseline remains
GKOS-2026-07-20 v0.76.

The prepared v0.77 material would:

- record R13 as an accepted v0.x development decision;
- require incomplete conformance runs to report `UNEVALUATED`, claim no
  profile, and exit non-zero;
- retain fixture catalog 0.1.1 as a starter, non-qualifying catalog;
- establish `GKOS-<AREA>-<NNN>` as the stable requirement-ID form and place
  implementation diagnostics behind adapter mappings;
- maintain the owner-accepted permanent allocations in
  `requirements/REGISTRY.md`, with R13-101 as the sole controlling
  identity-and-lineage decision; and
- record the corrected Engine-to-standard reconciliation v0.2 and its
  non-normative Engine diagnostic adapter map without turning Engine behavior
  into standard authority.
- require lowercase UUIDv7 for newly authored GKX note identities while
  preserving valid legacy lowercase UUIDv4 identities; relationship targets
  retain a broader UUID-or-policy-permitted-namespaced identifier grammar; and
- require branch-preserving lineage for any identity migration.

It would not qualify an implementation, make the reference Engine normative,
close the independent-implementation gate, ratify the draft portfolio registry,
or alter any published release package.
