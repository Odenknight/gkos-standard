# Release notes — GKOS-2026-09-03 v0.81

## Purpose

GKOS v0.81 is a developmental pre-standard designed to support AI governance,
accountability, and auditability. It makes the path from preserved evidence
through claims, deterministic controls, review, context, and authorized use
inspectable and testable. Publication does not demonstrate that these goals
have been achieved by any particular implementation.

## Changes from v0.80

- R17 defines captured action-evaluation time and half-open authority validity.
- R18 consolidates GCP-4/GCP-5 review lifecycle, bounded independent-agent
  review with mandatory human escalation, and protected-disclosure controls.
- R19 prospectively adopts the eighth documentation-intent invariant.
- R20 requires exact candidate evidence and separate final owner approval.
- The edition consolidates 62 permanent allocations and 28 diagnostic gates,
  including six allocations previously accepted but unpublished.
- Standard-owned graph evaluation, adversarial false-PASS protections, and
  portable mutation coverage remain part of the release gate.
- Publication tooling binds the exact commit and package hashes through a
  signed owner attestation and preserves historical RC evidence.

## Claims and limitations

This is a non-consensus, non-qualifying developmental pre-standard. No GKOS
Core, Advanced, Context-Only, GCP, or Viewer/Projection qualification is
created. Public second implementation remains awaiting. Implementation
divergences remain disclosed. R21 interoperability work is informative;
external protocols and vendor products are not normative v0.81 dependencies.
Protocol activation is not authorized and no certification program is
established. Previous release packages and allocation identities are preserved.

## Publication and archival identity

The planned publication date is September 3, 2026 and must match the actual
release date. The exact approved commit, passing mandatory checks, package
hashes, and owner approval are bound in the signed `v0.81` tag annotation.
Live status also requires successful post-tag checks and the GitHub Release.
Zenodo archival and DOI identities are recorded after ingestion and verification.
