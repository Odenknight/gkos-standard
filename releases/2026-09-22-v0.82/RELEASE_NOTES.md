# Release notes — GKOS-2026-09-22 v0.82

## Purpose

GKOS v0.82 is proposed as an **informative edition** of the developmental
pre-standard. It archives the post-v0.81 architecture, interoperability,
evidence and orientation work under a citable identity. The normative
requirement population is unchanged from v0.81.

## Changes from v0.81

- R22 canonical informative architecture r3 (documentation authority only).
- R23 accepted prospective Layer-3 interoperability semantics, with provisional
  L3 schemas, fixtures, comparator and the V82-01 work packet.
  `EAR-GRAPH-001..003` remain DRAFTING. Under R24 Option A, R23 is not
  normative in this edition; its normative target is the next normative
  edition after v0.82. The `proposed-v0.82` fixture identifier is historical.
- Provisional RRET-01 adversarial retrieval corpus and tests.
- Full-stack workflow walkthrough; informative ISO, EU AI Act and NIST
  middleware proposals and bounded pilot plan; updated Known Limitations annex.
- CIA triad alignment, domain guides, corpus status, restored graphics and
  practical explainers.
- Owner clarification on implementation independence (2026-09-12).
- R24 release gate and publication control (accepted 2026-09-22).

## Unchanged

62 permanent requirement allocations and 28 mandatory diagnostic gate codes.
No requirement text, gate predicate or profile applicability changes.

## Claims and limitations

This is a non-consensus, non-qualifying developmental pre-standard. No GKOS
Core, Advanced, Context-Only, GCP or Viewer/Projection qualification is
created. Public second implementation remains awaiting. Provisional material
creates no conformance obligation. External protocols and vendor products are
not normative dependencies. Protocol activation is not authorized and no
certification program is established. Earlier release packages, including
v0.81, are preserved unaltered.

## Publication and archival identity

The planned publication date is September 22, 2026 and must match the actual
release date. The approved commit, passing mandatory checks, package hashes
and owner approval are bound in the signed `v0.82` tag annotation. Live status
also requires successful post-tag checks and the GitHub Release. The Zenodo
version DOI is recorded only after ingestion is verified; the v0.81 DOI is
never reused.
